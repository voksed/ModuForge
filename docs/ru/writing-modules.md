# Как писать модули

Модуль — это папка с манифестом (`moduforge.json`) и кодом. Папка упаковывается в один
подписанный файл `.mfrg`, который пользователи импортируют в приложении.

Здесь описаны скриптовые модули на Lua. Про компилируемые — в разделе
[Модули на Kotlin](kotlin-modules.md).

## Быстрый старт

Нужны Java 17 или новее и этот репозиторий.

```
gradlew :tools:packer:installDist     один раз: собрать упаковщик
mfrg new                              задаст несколько вопросов и создаст папку проекта
mfrg pack <папка>                     соберёт <id>-<версия>.mfrg
```

`mfrg` — это `mfrg.cmd` в корне репозитория; в других системах запускайте
`tools/packer/build/install/mfrg/bin/mfrg`.

`mfrg new` предлагает три заготовки:

| Заготовка | Что получится |
|---|---|
| Telegram bot | Бот, который отвечает на `/start` и повторяет текст |
| Watcher | Каждые пять минут скачивает страницу и уведомляет, когда она изменилась |
| Empty script | Одна строка, которая пишет в вывод модуля |

Скопируйте `.mfrg` на телефон и импортируйте в приложении.

## Папка проекта

```
my-bot/
  moduforge.json     манифест
  main.lua           главный скрипт
  lib/util.lua       любые другие файлы, подключаются через require("lib.util")
```

Все файлы папки, кроме `moduforge.json`, становятся кодом модуля. В пакет не попадают и
перечисляются упаковщиком, если найдены: файлы `*.session`, `*.session-journal`, `.env` и
`.env.*`, а также каталоги `.git`, `.hg`, `.svn`, `.idea`, `.vscode`, `__pycache__`,
`node_modules`, `venv`, `.venv`. В именах файлов допустимы латинские буквы, цифры и
`_ . @ + -`.

## Манифест

```json
{
  "id": "com.example.mybot",
  "name": "Мой бот",
  "version": "1.0.0",
  "sdkRange": ">=1.0.0 <2.0.0",
  "runtime": "lua",
  "entry": "main.lua",
  "author": "Пример",
  "description": "Что делает модуль.",
  "permissions": ["NETWORK_OUTBOUND", "FILE_SANDBOXED"],
  "permissionReasons": {
    "NETWORK_OUTBOUND": "Общается с API бота.",
    "FILE_SANDBOXED": "Хранит токен."
  }
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | Имя в обратной доменной записи строчными буквами, уникальное на устройстве, не длиннее 128 символов. Никогда его не меняйте: другой id — это другой модуль |
| `name` | да | Показывается пользователю, 1–64 символа |
| `version` | да | [Семантическая версия](https://semver.org/lang/ru/), например `1.4.0` |
| `sdkRange` | да | Версии API модулей, которые вы поддерживаете. Пишите `>=1.0.0 <2.0.0` |
| `runtime` | нет | `lua` или `dex` (компилируемый). По умолчанию `dex`. `js` и `python` зарезервированы и отклоняются при установке |
| `entry` | да | Для `lua` — путь главного скрипта внутри папки. Для `dex` — имя класса |
| `permissions` | нет | Что модулю можно выдать. Всё, чего здесь нет, отклоняется без вопроса пользователю |
| `permissionReasons` | нет | Ваше объяснение каждого разрешения, его видит пользователь. До 300 символов; ключи должны быть перечислены в `permissions` |
| `author` | нет | Показывается пользователю |
| `description` | нет | Показывается перед установкой, до 2000 символов |
| `ui` | нет | `none` (по умолчанию) или `compose`; интерфейс есть только у компилируемых модулей |

Неизвестные поля и неизвестные названия разрешений делают манифест недействительным.

## Разрешения

| Название | Что открывает |
|---|---|
| `NETWORK_OUTBOUND` | `mf.http` |
| `FILE_SANDBOXED` | `mf.storage`, `mf.config` |
| `BACKGROUND_EXECUTION` | Работу, когда приложение не на экране; автозапуск |
| `NOTIFICATIONS` | `mf.notify` |

Перед запуском модуля приложение само показывает пользователю все заявленные разрешения,
которых у модуля ещё нет, вместе с вашими объяснениями. Запрашивать их в коде не нужно.
Если пользователь что-то не включил, вызовы, которым это нужно, вернут `nil` и сообщение;
скрипт продолжит работу.

`FILE_SHARED`, `CLIPBOARD`, `AI_INFERENCE`, `BOT_GATEWAY`, `DEVICE_INFO` и
`LOCAL_NETWORK_SCAN` в манифесте принимаются, но пока ничего не открывают.

## Как выполняется скрипт

- Главный скрипт выполняется сверху вниз в отдельном потоке, когда модуль запускают.
- Пока он выполняется, модуль «Работает». Бот — это скрипт с бесконечным циклом.
- Когда скрипт дошёл до конца или завершился ошибкой, модуль останавливается, а причина
  записывается в журнал аудита.
- Когда модуль останавливает пользователь, процесс уничтожается. Не рассчитывайте на код
  завершения.
- `require("name")` подключает `name.lua` из папки, `require("dir.name")` — `dir/name.lua`.
- Язык — Lua 5.2 с библиотеками `string`, `table`, `math`, `coroutine` и `bit32`. Нет
  `os`, нет `io`, нет файловой системы.

Весь API — в [справочнике Lua](lua-api.md).

## Секреты

Никогда не кладите в папку токены, пароли и файлы сессий: пакеты пересылают. Спрашивайте
их во время работы и храните в хранилище модуля — оно зашифровано на телефоне
пользователя:

```lua
local config = require("mf.config")
local token = config.get("token", { ask = "Токен API", secret = true })
```

## Подпись

Каждый пакет подписан. Без `--key` команда `mfrg pack` берёт ваш личный ключ и создаёт
его при первом использовании:

- расположение: `~/.moduforge/key.json` или файл из переменной окружения `MODUFORGE_KEY`;
- **никому его не передавайте и сохраните копию**. У кого есть этот файл, тот может
  выпускать обновления ваших модулей; потеряете его — не сможете вы.

Упаковщик печатает отпечаток ключа в строке «signer». Тот же отпечаток видит пользователь
при установке. Центра, который ручался бы за авторов, нет, поэтому опубликуйте свой
отпечаток там, где пользователи смогут его сверить.

## Обновление

1. Увеличьте `version` в `moduforge.json`.
2. Выполните `mfrg pack` с тем же ключом.
3. Пользователи импортируют новый файл.

Приложение принимает обновление, только если подпись та же, а версия не ниже. Модуль
должен быть остановлен. Его файлы и выданные разрешения сохраняются; выдачи разрешений,
которые вы убрали из манифеста, удаляются.

## Команды упаковщика

| Команда | Что делает |
|---|---|
| `mfrg new [папка]` | Мастер проекта с вопросами |
| `mfrg pack <папка> [--key файл] [--out файл.mfrg] [--dex apk-или-dex]` | Собирает и подписывает пакет |
| `mfrg verify <файл.mfrg>` | Проверяет пакет, печатает сводку манифеста и подписавшего |
| `mfrg keygen <файл>` | Создаёт ключ подписи в выбранном месте |
| `mfrg init <папка> --id … --runtime … --entry … [--name …]` | Записывает только заготовку манифеста |

## Ограничения

| Что | Предел |
|---|---|
| Код модуля в пакете | 64 МБ |
| Файлов в пакете | 10 000 |
| Один файл в хранилище модуля | 512 КБ |
| Хранилище модуля целиком | 64 МБ, 2000 файлов |
| Открытых соединений на модуль | 16 |
| Тело HTTP-ответа | 8 МБ |
| Текст вопроса пользователю | 500 символов |
| Уведомление | заголовок 80, текст 1000 символов |
| Строка вывода модуля | 4000 символов; приложение хранит последние 200 строк |

## Проверка на устройстве

1. Установите приложение (см. [Сборка из исходников](building.md)) и импортируйте пакет.
2. Включите модуль, нажмите «Запустить», включите разрешения.
3. Смотрите **Вывод модуля** на экране модуля: туда пишут `mf.log` и `print`.
4. После правки: поднимите версию, упакуйте, импортируйте снова.
