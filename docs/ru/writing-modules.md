# Как писать модули

Модуль — это скрипт на **Lua** или **JavaScript** плюс короткое описание того, что ему
нужно. Написать его можно тремя способами, от самого лёгкого к самому полному:

| Способ | Что нужно | Подходит для |
|---|---|---|
| [В приложении](#в-приложении) | Только телефон | Модуль для себя |
| [Скрипт на компьютере](#на-компьютере) | Инструмент `mfrg` | Удобная правка и отладка |
| [Подписанный пакет](#пакет-для-других-людей) | Инструмент `mfrg` | Передать модуль другим людям |

API везде одно и то же: [Lua](lua-api.md), [JavaScript](js-api.md). Готовые куски для
типичных задач — в [рецептах](cookbook.md). Компилируемые модули описаны в разделе
[Модули на Kotlin](kotlin-modules.md).

## В приложении

Не нужны ни компьютер, ни манифест, ни подпись.

1. На вкладке **Модули** нажмите **Создать модуль**, выберите язык и заготовку:
   Telegram-бот, наблюдатель за страницей или пустой скрипт.
2. Назовите модуль и правьте код.
3. Нажмите **Сохранить и запустить**. При первом запуске подтвердите разрешения.

Редактор:

- подсвечивает код и нумерует строки;
- над кодом есть ряд **подсказок** — `http`, `storage`, `config`, `telegram`, `ui` и
  другие; нажатие вставляет в место курсора готовый рабочий вызов;
- **Добавить файл** создаёт другие файлы модуля (`lib/util.lua`), которые главный скрипт
  подключает через `require`;
- если модуль остановился с ошибкой, на его экране появляется кнопка **Открыть main.lua,
  строка 12** — редактор откроется с курсором на этой строке.

Что приложение делает за вас:

- **Разрешения определяются по коду.** `mf.http`, `mf.connect` и `mf.websocket` заявляют
  доступ в интернет, `mf.storage` и библиотека `config` — хранилище, `mf.notify` —
  уведомления. Работу в фоне вы включаете в редакторе сами.
- **Версия растёт при каждом сохранении**; файлы модуля и выданные разрешения сохраняются.
- **Работающий модуль перезапускается** с новым кодом.

Готовый файл `.lua` или `.js` импортируется той же кнопкой, что и пакет: он открывается в
редакторе, где виден весь код, и становится модулем, когда вы его сохраните.

Такой модуль живёт только на вашем телефоне и не подписан. Чтобы отдать его другим людям,
сделайте [пакет](#пакет-для-других-людей).

## На компьютере

Нужны Java 17 или новее и этот репозиторий:

```
gradlew :tools:packer:installDist     один раз: собирает инструмент mfrg
```

`mfrg` — это `mfrg.cmd` в корне репозитория; в других системах запускайте
`tools/packer/build/install/mfrg/bin/mfrg`.

### Запустить прямо здесь: `mfrg run`

```
mfrg run bot.lua            один скрипт, манифест не нужен
mfrg run my-module          папка проекта
```

Модуль выполняется на компьютере тем же рантаймом, что и в приложении, с настоящим
доступом в интернет. Вывод идёт в терминал, вопросы `mf.ask` задаются там же, уведомления
и интерфейс печатаются текстом. Хранилище лежит в `.mfrg-run/` рядом с кодом, поэтому
настройки сохраняются между запусками. Остановка — Ctrl+C.

| Параметр | Действие |
|---|---|
| `--deny NOTIFICATIONS,FILE_SANDBOXED` | Вести себя так, будто пользователь отказал в этих разрешениях |
| `--allow-local` | Разрешить адреса локальной сети и этого компьютера, например тестовый сервер на `localhost`. На телефоне они остаются запрещены |

Для одиночного скрипта считается выданным каждое разрешение, которое использует его код, а
соседние скрипты находятся через `require`.

### Отправить на телефон: `mfrg push`

Одна команда упаковывает модуль, ставит его на телефон, перезапускает и показывает его
вывод:

```
mfrg push my-module
```

Настройка, один раз:

1. В приложении откройте **Настройки → Разработчикам модулей** и включите **Режим
   разработчика**.
2. Подключите телефон по USB с включённой отладкой по USB и выполните команду, показанную
   на этом экране, — в ней есть код сопряжения: `mfrg push --token XXXX-XXXX-XXXX-XXXX`.

Код и адрес запоминаются; дальше достаточно `mfrg push` в папке модуля. Чтобы работать без
кабеля, включите **Принимать по Wi-Fi** и один раз укажите адрес телефона:
`mfrg push --host 192.168.1.20`. Вернуться к USB можно через `--host usb`.

После отправки терминал печатает то, что пишет модуль, пока вы не нажмёте Ctrl+C; сам
модуль продолжает работать. `--no-follow` возвращает управление сразу после установки.

Что нужно знать:

- Чтобы принять модуль, приложение должно быть открыто (или какой-то модуль должен
  работать в фоне).
- Пакет подписывается вашим ключом и проверяется как любой другой; обновление должно быть
  подписано тем же ключом.
- Разрешения подтверждаются на телефоне. При первой отправке модуль не запускается, если
  ему нужны разрешения: `mfrg push` сообщит об этом, откройте модуль в приложении и один
  раз нажмите «Запустить». Дальше разрешения сохраняются, и каждая следующая отправка
  запускает модуль сама.
- Сам код сопряжения не передаётся; компьютер лишь доказывает, что знает его. Режим Wi-Fi
  используйте только в сети, которой доверяете, а закончив работу, выключайте режим
  разработчика.

### Проект

`mfrg new` задаёт несколько вопросов — название, язык, заготовка — и создаёт папку:

```
my-bot/
  moduforge.json     манифест
  main.lua           главный скрипт (main.js для JavaScript)
  lib/util.lua       любые другие файлы
```

Каждый файл папки, кроме `moduforge.json`, становится кодом модуля. Не попадают в пакет
(и упаковщик об этом сообщает) файлы `*.session`, `*.session-journal`, `.env` и `.env.*`,
папка `.mfrg-run` и каталоги `.git`, `.hg`, `.svn`, `.idea`, `.vscode`, `__pycache__`,
`node_modules`, `venv`, `.venv`. В именах файлов можно использовать буквы, цифры и
`_ . @ + -`.

Подключение других файлов:

| Язык | Вызов | Что загружается |
|---|---|---|
| Lua | `require("lib.util")` | `lib/util.lua` |
| JavaScript | `require("./lib/util")` | `lib/util.js` относительно текущего файла |

## Пакет для других людей

```
mfrg pack my-module         собирает <id>-<version>.mfrg, подписанный вашим ключом
```

Пользователи ставят файл в приложении: кнопкой **Импортировать файл**, открыв его из
файлового менеджера или чата, либо по ссылке на установку.

### Ссылка на установку

Выложите файл `.mfrg` туда, откуда его можно скачать по HTTPS (релиз на GitHub, ваш сайт), и
сделайте ссылку:

```
mfrg link my-bot-1.0.0.mfrg https://example.com/files/my-bot-1.0.0.mfrg
```

Команда напечатает ссылку вида `moduforge://install?...`. Опубликуйте её текстом или
превратите в QR-код любым генератором. Открытие ссылки на телефоне с ModuForge скачивает
пакет после согласия пользователя, а поскольку в ссылке есть отпечаток вашего ключа,
приложение само проверяет, что пакет подписан вами. Сверять отпечатки на глаз никому не
нужно.

### Манифест

```json
{
  "id": "com.example.mybot",
  "name": "My bot",
  "version": "1.0.0",
  "sdkRange": ">=1.0.0 <2.0.0",
  "runtime": "lua",
  "entry": "main.lua",
  "author": "Example",
  "description": "Что делает модуль.",
  "permissions": ["NETWORK_OUTBOUND", "FILE_SANDBOXED"],
  "permissionReasons": {
    "NETWORK_OUTBOUND": "Обращается к API бота.",
    "FILE_SANDBOXED": "Хранит токен."
  }
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | Имя в стиле обратного DNS строчными буквами, уникальное на устройстве, до 128 символов. Никогда не меняйте: другой id — это другой модуль |
| `name` | да | Показывается пользователю, 1–64 символа |
| `version` | да | [Семантическая версия](https://semver.org), например `1.4.0` |
| `sdkRange` | да | Версии API модулей, которые вы поддерживаете. Используйте `>=1.0.0 <2.0.0` |
| `runtime` | нет | `lua`, `js` или `dex` (компилируемый). По умолчанию `dex`. `python` зарезервирован и отклоняется при установке |
| `entry` | да | Для скриптов — путь к главному скрипту внутри папки. Для `dex` — имя класса |
| `permissions` | нет | Что модулю можно выдать. Всё, чего здесь нет, отклоняется без вопроса пользователю |
| `permissionReasons` | нет | Ваше объяснение каждого разрешения, его видит пользователь. До 300 символов; ключи должны быть перечислены в `permissions` |
| `author` | нет | Показывается пользователю |
| `description` | нет | Показывается до установки, до 2000 символов |
| `ui` | нет | `none` (по умолчанию) или `compose`. Ставьте `compose`, если модуль показывает интерфейс (`mf.ui`) |

Неизвестные поля и неизвестные имена разрешений делают манифест недействительным.

### Подпись

Каждый пакет подписан. Без `--key` команды `mfrg pack` и `mfrg push` используют ваш личный
ключ и создают его при первом использовании:

- расположение: `~/.moduforge/key.json` или файл, названный в переменной окружения
  `MODUFORGE_KEY`;
- **храните его в тайне и делайте копию**. Кто владеет файлом, может выпускать обновления
  ваших модулей; потеряете — не сможете выпускать их сами.

Упаковщик печатает отпечаток ключа как «signer». Пользователи видят тот же отпечаток при
установке. Центра, который ручается за авторов, нет: публикуйте ссылки на установку (в них
есть отпечаток) или сам отпечаток там, где его найдут ваши пользователи.

### Обновление

1. Увеличьте `version` в `moduforge.json`.
2. Выполните `mfrg pack` тем же ключом.
3. Пользователи ставят новый файл или открывают новую ссылку.

Приложение принимает обновление, только если ключ тот же, а версия не ниже. Файлы модуля и
выданные разрешения сохраняются; разрешения, убранные из манифеста, отзываются.
(`mfrg push` принимает и ту же версию, поэтому при разработке поднимать её не нужно.)

## Разрешения

| Имя | Что открывает |
|---|---|
| `NETWORK_OUTBOUND` | `mf.http`, `mf.connect`, `mf.websocket` |
| `FILE_SANDBOXED` | `mf.storage`, библиотека `config` |
| `BACKGROUND_EXECUTION` | Работу, когда приложения нет на экране; автозапуск |
| `NOTIFICATIONS` | `mf.notify` |

Перед запуском модуля приложение показывает пользователю все заявленные разрешения, которых
у модуля ещё нет, с вашими пояснениями. Запрашивать их в коде не нужно. Если пользователь
что-то не включил, вызовы, которым это нужно, отказывают мягко — `nil` и сообщение в Lua,
`Error` в JavaScript, — а скрипт продолжает работать.

`FILE_SHARED`, `CLIPBOARD`, `AI_INFERENCE`, `BOT_GATEWAY`, `DEVICE_INFO` и
`LOCAL_NETWORK_SCAN` принимаются в манифесте, но пока ничего не открывают.

## Как выполняется скрипт

- Главный скрипт выполняется сверху вниз в собственном потоке, когда модуль запускается.
- Пока он выполняется, модуль «Работает». Бот — это скрипт с бесконечным циклом.
- Когда скрипт доходит до конца или падает, модуль останавливается. Причина с файлом и
  строкой ошибки — в выводе модуля и в журнале аудита.
- Когда пользователь останавливает модуль, процесс уничтожается. Не рассчитывайте на код
  очистки.
- Файловой системы и доступа к другим приложениям нет: всё идёт через `mf`.

## Настройки и секреты

Никогда не кладите токены, пароли и файлы сессий в папку: пакеты передают дальше. Спрашивайте
их во время работы и храните в хранилище модуля, которое шифруется на телефоне
пользователя:

```lua
local config = require("mf.config")
local token = config.get("token", { ask = "Токен API", secret = true })
local interval = config.get("interval", { label = "Секунд между проверками", default = 300 })
```

Каждое значение, прочитанное так, появляется на экране модуля в карточке **Настройки**, где
пользователь может позже его изменить; модуль перезапускается с новым значением. Писать
экран настроек самому не нужно.

## Что делает модуль: вывод и отладка

- `mf.log` (а также `print` и `console.log`) пишет в **Вывод модуля** на экране модуля.
  Хранятся последние 500 строк, в том числе после перезапуска приложения.
- **Поделиться** отправляет вывод текстом — удобно, когда пользователь сообщает вам о
  проблеме.
- Когда скрипт падает, в выводе есть сообщение, файл и строка.
- `mfrg push` печатает тот же вывод в вашем терминале.

## Команды `mfrg`

| Команда | Что делает |
|---|---|
| `mfrg new [dir]` | Интерактивный мастер проекта |
| `mfrg run <dir-или-скрипт> [--deny …] [--allow-local]` | Запускает скриптовый модуль на этом компьютере |
| `mfrg push [dir] [--token …] [--host …] [--no-follow]` | Ставит на телефон, перезапускает модуль, печатает его вывод |
| `mfrg pack <dir> [--key file] [--out file.mfrg] [--dex apk-или-dex]` | Собирает и подписывает пакет |
| `mfrg link <file.mfrg> <https-адрес>` | Печатает ссылку на установку для выложенного пакета |
| `mfrg verify <file.mfrg>` | Проверяет пакет и печатает сводку манифеста и подписанта |
| `mfrg keygen <file>` | Создаёт ключ подписи в выбранном месте |
| `mfrg init <dir> --id … --runtime … --entry … [--name …]` | Пишет только шаблон манифеста |

## Ограничения

| Что | Предел |
|---|---|
| Код модуля в пакете | 64 МБ |
| Файлов в пакете | 10 000 |
| Один файл в хранилище модуля | 512 КБ |
| Хранилище модуля целиком | 64 МБ, 2000 файлов |
| Открытых соединений на модуль | 16 |
| Тело HTTP-ответа | 8 МБ |
| Перенаправлений, которым следует `mf.http` | 5 по умолчанию, не больше 10 |
| Текст вопроса пользователю | 500 символов |
| Уведомление | заголовок 80, текст 1000 символов |
| Одна строка вывода модуля | 4000 символов; приложение хранит последние 500 строк |
